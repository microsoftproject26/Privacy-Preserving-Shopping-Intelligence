## 2. The key finding after the sitting: FedAdam tau

- **The mechanism.** The registered FedAdam tau = 1e-3. Every FL arm (benchmarks and REES46) had about 100 % of its per-round
  update values below tau. The server step was therefore 20–100× too small. W* MAIN moved only about 0.06 % from θ_pre over
  13,654 rounds (MEASURED; DL 528, 540, 546).
- **On the benchmarks, the fix works.** With tau 1e-6, a larger budget (B24) and unfrozen items, validation NDCG@10 of the best
  FL arm as a percentage of C_FULL (D256) is:

  | Dataset | Retention |
  |---|---|
  | beauty | 79.5 |
  | sports | 79.6 |
  | toys | 91.3 |
  | video_games | 75.9 |
  | baby_products | 82.2 |
  | ML-1M | 89.4 |

  The confirmatory TEST runs were 13–81 % (DL 551–552).
- **On REES46, the fix does not change the answer.** Larger steps on top of the strong 1.2M-user θ_pre *hurt* CALIB: eta 3e-5
  drops 0.1705 → 0.1663 (DL 542). K21 and Q1 are therefore robust, not a tau artefact.
- **PB100 shows that FL value depends on the server data.** PB100 is θ_pre trained on 100k users only. Its exploratory TEST
  (DL 542, register entries 12 and 13):

  | Comparison (MRR@20) | Value |
  |---|---|
  | FA_WARM_PB100K − PRE100K | **+0.0074** [0.0064, 0.0084] |
  | Retention vs C_FULL | 73.8 → 77.9 |
  | The 1.2M θ_pre, for comparison | 88.8 |

  The less data the server has, the more FL adds.
