## How to read this file

- **"DL n" means the decision-log row whose `#` column is n.** The file line is not the row number. Known quirks: row 169 exists twice (the second is cited 169b); rows 354–363 exist twice (the second copies are monitoring-only rows from a cron session, see the erratum in DL 377); row 377 exists twice (the erratum and the Wave-2 decision). Where I cite one of these numbers I say so or cite both.
- **Paths** are relative to `ppsi_v4/` on the server (`/home/jovyan/…/ppsi_v4/`). I copied each path from a log row. If the log gives no path I write "not stated". Local-only records are under `company/`.
- **Status:** DONE, ABANDONED (stopped or dropped, including "declared not run"), FAILED (ended in error and was not completed as such), SUPERSEDED (replaced by a later version; kept as history). A line in "Status" that adds "UNCLEAR" means the log has no closing row.
- **Label.** CONFIRMATORY = a registered contrast read under its registered rule (including the single VALIDATION read, which is not the final number). EXPLORATORY = tuning, selection, screening and everything done after the VALIDATION read ("POST-HOC" is added for runs after 2026-10-03T15:04Z, DL 400). DESCRIPTIVE = reported, never selected on, no claim. SMOKE = infrastructure, probe or verification run, not evidence.
- **Key result** is copied from the log with its DL source. Values labelled VALIDATION are max-of-marks and are not the final numbers; the single TEST look (T0a) holds the final numbers (section 6).
- **Metric** unless stated: client-macro MRR@20 (higher is better). "PB" = PRACTICAL_BEST (best validated mark within the budget); "CB" = CONTROLLED_BUDGET (fixed endpoint). "EFE" is the exposure budget unit (its expansion is never written in the records).
- **Ambiguous rows** are marked **[AMBIGUOUS]** with the reason.

Abbreviations for arms: C_BIG / C_SMALL / C_FULL = central cloud models (D256_B3 on 131,072 users / D64_B2 on the same users / D256_B3 on 1,348,682 users); FA = FedAvg-family federated arm; FP = FedProx; PF = personalised FL; FA_Q8 = 8-bit uploads; FA_1024 = z=0 twin of the DP arms; DP8 / DP1 = central DP with epsilon 8 / 1; LO = device-only; FT_x = on-device fine-tune of x; PRE = θ_pre, the model pretrained on 1,217,610 non-MAIN users; FA_WARM / FA_WARM_FROZEN = FL started from PRE (frozen = item tables frozen); W* = the Phase-2 warm-FL winner.
