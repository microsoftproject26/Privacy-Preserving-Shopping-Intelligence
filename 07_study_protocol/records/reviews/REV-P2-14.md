### Console-marker capture
`--headless=new --enable-logging=stderr --v=0`: Chromium prints console messages to stderr at INFO as `[pid:tid:time:INFO:CONSOLE(line)] "<msg>", source: <url> (line)`; INFO is the default minimum, so `--v=0` is fine, and this should work with headless=new (UNVERIFIED on Edge 146-152; run one 10 s smoke test per version). Weak points: the message is not escaped (the `rfind('", source:')` parse copes); very long lines and interleaved stderr noise are not guaranteed safe (the JSON is a few KB of summary stats, so probably fine, untested); the FATAL marker counts as success (M3). `--dump-dom` is unsuitable (fires at load; `--virtual-time-budget` distorts performance.now).
Recommended robust method: a localhost-only result sink in serve_coi.py, used for SERVER_BROWSER runs only. `POST /__p2_result?tag=<TAG>` accepted only if the client is 127.0.0.1, `Origin` equals the server origin, Content-Length <= 1 MB, valid JSON with the expected `schema`, tag matching `^[A-Za-z0-9._-]+$`; written to `--results-dir/<tag>.json` only; all other POSTs keep returning 405. The page POSTs (same origin, relative URL) only when `?sink=<tag>` is present; the laptop flow never uses it. Update the "no upload" test to allow exactly this call. The shell waits for the file and checks `error`; stderr stays as a secondary log. Alternative: CDP via `--remote-debugging-pipe` (Python client on fds 3/4, `Runtime.consoleAPICalled`), more code.
