## 2. Findings

**R1 (required before P2-T3 is used; fail-closed). The receipt format does not match `p2_select`.**
- What the handoff writes (P2-01_02.md:228-252): a receipt with {format PPSI_V4_P2T3_RECEIPT_1, verdict PASS|FAIL,
  checks, s8tc_run_dir, p2_run_dir, train-loss shas, code_tree}.
- What `p2_select.check_p2t3_receipt` requires (p2_select.py:141, :773-791): `test: "P2-T3"`,
  `verdict: "BIT_IDENTICAL"`, `rounds: 64`, `s8tc_run_id` equal to S8Tc's RESULT_ROWS `run_id`, and `result_rows_sha256`
  / `run_summary_sha256` equal to sha256 of S8Tc's RESULT_ROWS.json / RUN_SUMMARY.json bytes.
- Consequence: the handoff's next step, `p2_select --incumbent-phase1 <S8Tc> --p2t3-receipt …` (:254), will always be
  refused, and the incumbent would have to be re-run.
- Fix: in the receipt script,
  - emit those keys, with verdict "BIT_IDENTICAL" only when every check passes (else "FAIL");
  - take `s8tc_run_id` from ARM_SPEC `run_id` (or RESULT_ROWS `run_id`; hash the bytes without reading values);
  - keep the current checks as extra fields.

**m2. P2-T3 evidence scope and robustness** (handoff §7):
- (a) TRAIN_LOSS line r depends on θ_r. So 64 exact lines are strong evidence for θ_0…θ_63, not a proof, and update 64
  is not covered. Fixes:
  - Raise `P2_MAX_SMOKE_ROUNDS` to 65 (P2-only constant, :323) and compare 65 lines, so the 64th update is covered.
  - Record the P2 smoke's `server_digest` in the receipt.
  - Word the result as "TRAIN_LOSS-exact".
- (b) Also compare INCUMBENT_COMPARED `exposure_budget`, `max_rounds` and `role`. Otherwise a PASS receipt can still be
  refused by `_same_common`, because the r5-era S8Tc spec text is untested here.
- (c) `> P2T3_RECEIPT.json` creates an empty file when the script asserts. Write it from Python only on success.

**m3. Code-tree discipline** (process; INFERENCE from 06E §8 + the lock):
- Never overlay P2 files on code_ds3r7 / r7b.
- P2 runs cannot resume across P2 trees. When P2-03 / P2-04 change fl/*.py or launch_fl, WA runs started on code_p2r1
  must finish there.
- P2_METHODS_LOCK (S1, "the code-tree digest") must therefore list every P2 tree, as ALL_METHODS_LOCK `code_trees`
  does, not only launch_fl c6192343.
- tools/p2_noop_check.py lives outside the code tree. Bind its sha separately.

**m4. Stale handoff text.** §0 / §6b say P2-06 "still needs its own read_p2_run"; it now exists (R1–R12). Q3 is
resolved: `p2_select.ANCHOR_MIN_GAIN` is 0.001.

**m5. A descriptive log can block completion.**
- `update_norm_summary` raises on non-monotonic rounds (launch_fl.py:1510), and `read/trim_update_norm_log` raise on a
  torn last line.
- Either would stop RUN_SUMMARY at the end of a run, and the run would stay blocked on every resume. This is the same
  pattern as Phase-1 TRAIN_LOSS, and the probability is low.
- Optional P2-only hardening: flag it, do not raise.
